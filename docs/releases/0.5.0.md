# Prob4D 0.5.0

Release date: 2026-08-12

Prob4D 0.5.0 is an intentionally incompatible cleanup release. It removes
unversioned compatibility conveniences and provider-v1 execution while
preserving portable contracts and immutable historical evidence.

## Removed

- All historical `prob4d-*` console-script aliases. The package installs only the
  grouped `prob4d` executable.
- `prob4d.legacy_cli`, its migration descriptor, migration workflow, and
  alias-specific tests.
- `prob4d commands migrate` and legacy-alias metadata from the command registry.
- `prob4d observation export-v1`, `prob4d.api.v1`, and provider-v1 estimator and
  export entry points.
- The broad lazy package-root export façade and large compatibility typing stub.

## Changed

- `import prob4d` exposes only `__version__`.
- Current downstream integrations import `prob4d.api.v2`.
- Provider-manifest CLI output is always provider API v2; `--api-version` was
  removed.
- Public API manifest schema version 2 records only the minimal root and current
  v2 façade.
- The command registry contains only canonical grouped routes.
- Source-distribution and wheel smoke tests prove that retired modules and
  executables are absent.

## Historical artifact compatibility

The package retains a narrow `prob4d.provider_v1` artifact compatibility bridge.
It contains immutable v1 record types, schema-v3 factor IO, observation IO,
causal binding, and manifest metadata required to inspect frozen evidence and to
exercise the three-repository contract corpus. It contains no provider-v1
estimator or exporter.

To reproduce a provider-v1 run, pin Prob4D 0.4.1 and its exact source/model
revisions. Historical content-addressed artifacts, repository identities, and
schema identifiers must not be rewritten.

## Command migration

```text
prob4d-validate-observation                 -> prob4d observation validate
prob4d-export-calibrated-observation-belief -> prob4d observation export-calibrated
prob4d-evaluate-provider                    -> prob4d evaluate provider
prob4d-target-admit                         -> prob4d provider target-admit
prob4d-target-verify                        -> prob4d provider target-verify
```

```python
# removed
from prob4d import Sim3

# current
from prob4d.api.v2 import Sim3
```

## Scientific boundary

This release changes packaging, command dispatch, Python import boundaries, and
interoperability metadata. It changes no estimator equations, calibration fit,
provider output, target-access rule, fallback decision, dataset split, or
scientific result. Passing the updated compatibility suite is not evidence of
provider accuracy, physical-query benefit, Causal4D intervention benefit,
deployment safety, or state of the art.
