# Release build identity

Prob4D claim-bearing exports must identify the code that is actually executing.
A normal wheel installed from a package index usually does not retain Git
`direct_url.json` metadata, so package version alone cannot establish an exact
source revision.

Prob4D distributions therefore carry a generated
`prob4d/_build_identity.json`. The build hook records:

- the exact source Git revision when the distribution was built from the
  repository;
- whether the complete source checkout was clean, including untracked files and
  submodule state;
- whether a wheel inherited its revision from an already identified source
  archive; and
- a deterministic SHA-256 manifest over every installed `prob4d` package file,
  excluding only the identity record itself and interpreter-generated bytecode.

The identity is generated in wheel or source-distribution staging. It is not
written into the working source tree. A wheel rebuilt from the source
distribution retains the original source revision and recomputes the manifest for
its own installed package bytes.

## Runtime behavior

`prob4d.runtime_revision.assert_runtime_revision(...)` resolves provenance in
this order:

1. a present and valid installed build identity;
2. historical PEP 610 VCS installation metadata;
3. an entirely clean source checkout; and
4. an environment assertion for exploratory recording only.

A present build identity fails closed if its package manifest, revision, or clean
source declaration is invalid. It is not bypassed by weaker `direct_url.json` or
environment metadata. Source-checkout attestation now includes untracked files;
an untracked Python module, configuration, protocol, or other file therefore
invalidates claim-bearing execution.

## Inspect an installed artifact

```python
from importlib import resources
import json

from prob4d.runtime_revision import assert_runtime_revision

expected_revision = "<exact-40-or-64-character-commit>"
identity_path = resources.files("prob4d").joinpath("_build_identity.json")
identity = json.loads(identity_path.read_text(encoding="utf-8"))
attestation = assert_runtime_revision(expected_revision)

assert identity["source_revision"] == expected_revision
assert attestation.independently_verified
```

The release workflow builds both wheel and source distribution, installs each in
an isolated environment outside the checkout, verifies the exact revision, and
checks that package-byte tampering is rejected.

## Trust and scientific boundary

The embedded identity binds installed package bytes to the revision declared by
the build process. It does not replace signed Git tags, published wheel and
source-archive SHA-256 values, an SBOM, build provenance, independent review, or
the content-addressed three-repository evidence capsule. Those external release
artifacts remain necessary to authenticate who produced the distribution and to
bind it into a scientific protocol.

A valid build identity establishes software provenance and package integrity
only. It does not establish provider accuracy, uncertainty calibration,
BayesianPhysTwin benefit, Causal4D intervention benefit, deployment safety, or
state of the art.
